📌 TIL 2026-01-29: React 및 API 안정성 해결

- React Strict Mode로 인한 OAuth 인증 코드 중복 전송 이슈를 useRef 플래그로 해결

- 라우터 구조 설계 오류 및 Redux 초기화 미비로 발생한 화면 전환/로그인 유실 문제 수정

- DB 제약 조건에 맞춰 서버 응답을 null 대신 빈 리스트로 수정하여 런타임 에러 방지

문제 해결 기록
현상: 소셜 로그인/회원가입은 성공하지만, 화면에 "로그인 처리 중 오류가 발생했습니다"라는 알림이 뜸. (콘솔에 500 에러 포착)
원인: React Strict Mode에 의해 useEffect가 2번 호출됨 → 일회성 인증 코드(code)를 두 번 전송함 → 서버에서 이미 사용된 코드에 대해 에러 응답.
해결: useRef를 사용하여 첫 번째 호출 여부를 추적하고, 중복 호출을 차단(Flagging)함.
-> 이 내용은 나중에 프로젝트 회고나 기술 면접에서 "React의 렌더링 특성과 OAuth의 보안 정책 사이의 충돌을 어떻게 해결했는지" 설명할 때 아주 좋은 답변이 될 것

화면 전환 불일치: 페이지 이동 시 URL만 바뀌고 화면은 그대로 멈춰 있어, 사용자가 매번 수동으로 새로고침을 해야만 내용이 바뀌는 현상.
로그인 상태 유실: 로그인을 성공한 직후 마이페이지 등으로 이동할 때, 새로고침을 하면 로그인 상태가 풀려버리는 현상.
심각한 내비게이션 지연: 헤더의 로그인/회원가입 버튼 등을 눌렀을 때 반응이 매우 느리고 즉각적으로 화면이 넘어가지 않는 문제.
라우터 구조 설계 오류: BrowserRouter가 앱 최상단이 아닌 App.tsx 내부에 있었고, 로딩 상태에 따라 라우터 자체가 통째로 사라졌다 나타났다 하며 상태를 초기화함.
인위적인 지연 시간: 코드 내에 2초간의 강제 대기 시간(setTimeout)이 설정되어 있어 모든 진입 과정에서 지연 발생.
Redux 초기화 로직 미비: 새로고침 시 로컬 스토리지의 토큰을 확인하지 않고 isLoggedIn을 항상 false로 시작하도록 설정되어 있었음.
스크롤 컨테이너 충돌: 메인 페이지와 레이아웃 양쪽에서 스크롤 및 스냅(snap-y) 기능이 중복 작동하여 브라우저 렌더링 성능 저하 유발.
백엔드 DB의 NOT NULL 제약 조건과 프론트엔드의 데이터 참조 오류를 방지하기 위해, 질문 토픽이 없을 경우 서버에서 null 대신 빈 리스트([])를 반환하도록 API를 수정하여 면접 진행 중 발생하는 런타임 에러를 해결함
